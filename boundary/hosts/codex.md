# Host binding — Codex (OpenAI Codex, desktop / CLI) on Windows

What Codex reads, what (does not) enforce the boundary, and the host facts the
interview must record. Enforcement on this host is **prompt-level only** — no
adapter row exists — so a pointer in `AGENTS.md` plus the skill's §0.2 gate are
the whole guard. Codex's own sandbox (`sandbox_mode`) is a separate mechanism
and does not know this layout. The measured host layout ships with the rule
text as
[`reference/hosts/codex.md`](../../skill/kalcirite-project-rules/reference/hosts/codex.md).

Install shape (two skills, one skill root, plus the standing pointer):

```
<userprofile>\.codex\
├─ AGENTS.md                                 <- one line: skill name + boundary file
└─ skills\
   ├─ kalcirite-project-rules\               <- clean install (empty local profile)
   └─ kalcirite-project-boundary\
      ├─ SKILL.md
      └─ PROJECT-BOUNDARY.md                 <- §0.1 step 2
```

Delegation runs on multi-agent v2: children are **agents defined in
`<userprofile>\.codex\agents\*.toml`** (`name` / `model` / `model_provider` /
`model_context_window`); the active provider route and the agent ceilings live
in `<userprofile>\.codex\config.toml` (`model_provider`, `[agents]`,
`[features.multi_agent_v2]`).

The six host facts, answered for Codex:

| Fact | Codex |
|---|---|
| delegation tools | spawn agent under `features.multi_agent_v2`, agents from `<userprofile>\.codex\agents\*.toml` → `DELEGATION_TOOLS = spawn agent (multi_agent_v2)` |
| can a delegation pick a model | no per-call field — the child's model is pinned in its toml → `ROUTE_SELECTION_SUPPORTED = none` |
| route discovery | the agent tomls + the active catalog (`model_catalog_json` in `config.toml`; on many machines a model-switching companion such as cc-switch owns both) |
| enabling route selection | edit `agents\*.toml` (hand-edits may be re-generated by the companion on catalog refresh) → `ROUTE_ENABLE_SETTING = agents/*.toml (via model-switch companion)` |
| when it takes effect | next spawn of that agent (unverified — confirm) |
| concurrency or budget ceiling | `config.toml [agents]` `max_concurrent_threads_per_session` / `max_depth` → `CONCURRENCY_LIMIT` |

A Codex boundary carries the same key set as a DSH boundary; the rows that
differ are `HOST_AGENT = Codex` and the ROUTE rows above. See
[`../MACHINE-CONFIG.template.md`](../MACHINE-CONFIG.template.md) for the full
template and [`../QUESTIONS.md`](../QUESTIONS.md) for why the facts are
recorded at all.
